# v0.1.0 remediation

This follows the [readiness review](2026-09-05-v0.1.0-review.md). Changes are made on the working
tree based on `524aaa6`, preserving the concurrent frontend release work. Nothing has been tagged,
published or deployed by this remediation. The earlier reports and reproduction package describe
the pre-fix code; the default suites now contain corrected-behavior regressions.

## Additional changes

- Signer proofs use immutable activity checkpoints, with monotonic activity IDs and a maximum
  submission age of `min(maxInactiveBlocks, 7200)` blocks. New votes no longer invalidate a proof
  already being prepared. The operator refreshes aging checkpoints before buying a proof. This
  evaluates inactivity as of the authenticated checkpoint, so accepted activity may be up to the
  policy window plus that bounded proving lag old at submission. Top-N validation is centralized.
- Parent authority is resolved once at installation and then pinned. Registry/controller changes
  cannot redirect child administration. Child Safe governance explicitly approves replacements,
  invalidating queued actions. Recovery proposer changes likewise invalidate all earlier queued
  actions. Delayed parent/recovery actions expire 14 days after becoming executable.
- Distributor pauses preserve claim time. `claimDeadline` remains the original configured value;
  `effectiveClaimDeadline` is the enforced deadline. The claim hook reads the effective value before
  classifying a finite round as expired or allowing a claim. Old expired rounds never reopen.
- Vault binding/migration requires accepted-state provenance before accepting funds. Snapshot
  state, provenance and checkpoint bookkeeping are complete before hooks run; lifecycle reentry is
  blocked.
- Solidity is pinned to 0.8.36. A persistent pnpm patch changes the EAS 1.9.0 dependency's exact
  pragmas to the same compiler without altering dependency logic. The patch and frozen lockfile are
  validated. Canonical external contracts are still identified by their actual deployed artifacts.

## Release impact and remaining evidence

The changes require new contract deployments and new verification keys for affected guests. Four
golden artifacts changed: trustgraph, contributions, Hypercerts and Nostr. No old deployment address
or verification-key record was relabeled. The standard signer journal ABI stays unchanged, but its
guest relation is stricter and therefore its key must be rebuilt.

The full [candidate and promotion procedure](../operations/v0.1.0-release-gates.md) defines the
remaining evidence. Real-proof CI checks the verifier adapter on a read-only gateway fork. Complete
factory-to-snapshot/signer transitions, funding/claims, governance/recovery and migration must also
be exercised on the exact testnet candidate before mainnet.

Native attestation ingress remains permissionless. No lifetime cap was added to the signer guest,
because that would permanently stop old instances. These fixes do not provide incremental proofs
or an economic admission mechanism. The current host profile, 80% alert and explicit migration
procedure remain necessary; recalibrate cycle costs for the new guests. A funded mainnet launch
still requires a resolved admission/capacity policy and a full governed-module migration rehearsal.

Imported programs now make availability a liveness requirement rather than a private scoring
choice. Admitted relayers must validate payloads and preserve archives. Existing-schema EAS imports
still authenticate the imported subset; they do not prove that all external source events were
imported. Those program guarantees are unchanged.

The mainnet deployment writer remains disabled. A final independent review and exact-candidate
testnet evidence are release gates, not claims made by this code change.
