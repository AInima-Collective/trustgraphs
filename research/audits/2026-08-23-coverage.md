# Solidity coverage disposition — 2026-08-23

No repository-wide Solidity coverage percentage can be produced with Foundry 1.7.1 and solc
0.8.27. Both compilation paths fail before any instrumented test executes:

1. `forge coverage -j1 --report summary` disables the optimizer and `viaIR`, then fails with
   `Stack too deep` at `contracts/src/merkle/MerkleSnapshot.sol:473` while compiling the
   `outputRoot` checkpoint call.
2. `forge coverage -j1 --ir-minimum --report summary` enables minimally optimized `viaIR`, then
   fails with a Yul stack-depth exception (`expr_3234_address is 1 too deep in the stack`). The
   compiler does not emit a source location for this failure; the pre-testnet audit's isolated run
   localized the equivalent `viaIR` failure to `TrustgraphsParamsController.sol:17`.

Both commands compile all 383 Solidity inputs and fail at compile time, so narrowing the test
matcher cannot produce a valid protocol-wide denominator. Excluding either failing production
contract would also exclude central scoring and parameter-control code and yield a misleading
percentage. The M4 response is therefore direct suites for the previously untested high-risk
contracts plus this reproducible compiler-blocker record, not a partial number presented as full
coverage.
